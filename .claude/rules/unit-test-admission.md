# 测试准入标准

每个用例必须回答一个问题：「未来哪个 diff 会让它变红？」如果唯一答案是「改测试自己」，删掉它。

新用例必须属于以下三类之一：

1. **Bug 回归。** 守卫真实发生过的 bug（CI 失败、issue、事故）。提交前验证它在修复前代码上失败、修复后通过；docstring 用黑盒语言描述 bug 机制，根因分析留给 issue 和 PR。
2. **推导不变量。** 沉淀需要推导才成立的结论——边界与对齐数学、mask 和负分支契约、协议语义（round-trip、幂等、顺序）。防住「看起来等价」的改写。
3. **关键路书记。** 防「加了 X 忘了同步 Y」——注册表完整性、字段生命周期、序列化兼容；枚举式断言在这里是允许的。

不接收：快乐路径的同义反复；把实现逻辑抄成断言的镜像测试；无法复现所声称失败的随机压测。

## 区分测试：删掉它，会留下静默失败路径吗

「看起来平凡」不是删除理由。判断标准不是「被测代码简单吗」，而是「删掉这个用例后，某个回归还能通过所有剩余测试吗」。以下断言要保留：

- **负分支契约。** `test_scatter_leaves_other_rows_untouched` 断言未被选中的行原样保留——「只写选中的行、不写整块」这个失败模式没有别的用例覆盖。
- **外部来源的字面量。** 外部规范定死的值（协议字段名、checkpoint 键名、供应商 API 形状）——删掉就没人防「把规范抄错」。
- **完整性与缺省语义。** 「所有内置项都注册了」「不匹配的输入不触发」「输入缺席时套用缺省值」。

真镜像才删：断言只是回显某个孤立实现输出，改了它仓库里没有别的东西会坏，这个用例就没有独立守卫价值。

## 组织与工程约定

- **默认加入同子系统既有文件**（kernel 用例进 `tests/kernels/test_*.py`）；新文件只在需要不同 fixture、依赖、owner 或 CI 契约时建。
- **分层用 marker**：`tests/kernels/` 自动带 gpu marker；CPU 也能跑的路径在 cpu 层补对应用例。
- **参考实现从 `tests/reference.py` 引入**（纯 torch、可读优先），不复制进各测试文件。
- **容差显式具名**：模块级 `_RTOL` / `_ATOL` 常量，与同 kernel 既有用例对齐；不散落魔法数。
- **输入构造要能暴露被守卫的失败模式**（边界、ragged、非单调、难数值输入），不要只采样「正常形状」的随机数据。
